# CaptureLab 0.5.0

Development date: 2026-10-01. Target release: v0.5.0.

This version improves everyday screenshot editing and reference workflows.

## Scope

- Set annotation color, line width, and font size. Changes apply to the selected
  annotation and become the defaults for subsequent annotations.
- Select and apply a crop in the editor, using source-pixel dimensions. Crop
  merges rendered annotations so mosaic redactions remain visible. Undo restores
  the original image and editable annotations; Redo restores the crop.
- Undo and redo annotation creation, edits, deletion, clearing, style changes,
  and crops. A new edit after Undo starts a new branch of edit history.
- Pin the current edited image or a history item in an independent floating
  window. Resize it, adjust opacity, and close it with Esc or Command-W.
- Browse every retained history item in a thumbnail grid. Open, copy, save,
  upload, pin, refresh, and delete an item after confirmation.

Quick-access overlays, scrolling capture, recording, project-file persistence,
cloud link management, and additional export formats remain future work.

## Acceptance and validation

- Preview and exported pixels use the same color and source-pixel metrics.
- Crop preserves source orientation and Retina pixel dimensions. Empty and
  non-finite selections are rejected without altering the editor.
- Rendering failure cannot crop or pin the unredacted source as a fallback.
- Undo and Redo restore both image and annotations. Replacement documents clear
  edit history. Cropping invalidates pending OCR and upload completions.
- Annotation drags survive selection-triggered view refreshes. Actual external
  undo, deletion, source, tool, or zoom changes cancel the pending gesture.
- Annotation-only Undo and Redo preserve corrected OCR text and pending source
  recognition. Image-changing transitions keep stale-request isolation.
- Counter numbers stay readable on light and dark fills in preview and export.
- All retained captures can be browsed, not only the recent-menu subset.
- History mutations merge the latest disk state under the existing process lock.
  Failed metadata writes keep referenced images available. Crop dimensions and
  the replacement image are committed together.
- Interrupted image-update temporary files are reclaimed after acquiring the
  history lock. Unknown names, directories, and symbolic links are preserved.
- Crop Escape cancels the selection while Command-W still closes the editor.
- Pinned windows stay above other app windows and release their managed reference
  on close. Pins are hidden during capture with the other CaptureLab windows.

Automated validation uses isolated synthetic images, temporary history storage,
independent pasteboards, and in-memory test credentials. Distribution signing,
DMG packaging, and publication belong to the subsequent release workflow.

## Verified on 2026-10-01

- Full Xcode: `swift test -Xswiftc -strict-concurrency=complete` passed all 230
  tests with no failures or compiler warnings.
- Seven confirmation probes from the independent review also passed after the
  fixes: active drag synchronization, OCR preservation during ordinary undo and
  redo, interrupted temporary-image cleanup, counter contrast, and history retry
  and deletion combinations. The probes ran against a separate source snapshot.
- Release builds passed for `arm64-apple-macosx13.0` and
  `x86_64-apple-macosx13.0`, including the update helper. Mach-O architectures
  matched both requested targets.
- A real AppKit fixture-window smoke test verified the minimum editor width,
  the rendered second toolbar row, and Escape cancelling a crop without closing
  the editor. Its screenshots contain only generated fixture content.
- The visual check found and resolved native-canvas drawing over the options
  row. The canvas now clips drawing to its bounds, and both toolbar rows share
  the top overlay.
- `git diff --check` passed. Build output and fixture screenshots stay ignored.

Intel hardware execution, macOS 13 execution, and interaction with real multiple
displays/fullscreen Spaces still need manual acceptance. Real-account upload,
distribution packaging, installation, and publication were not part of this
development pass.
